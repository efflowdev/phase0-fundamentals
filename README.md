# phase-0-fundamentals

One week of building the layers that LLM frameworks hide, without the frameworks. No LangChain, no
`openai` package, no vector database, no ORM — each day implements the thing an abstraction would
have provided, measures it, and writes down what the measurement contradicted.

Every claim in every day's write-up is a number produced by code in this repo, and every number can
be regenerated by the commands in that day's *Reproducing* section. Where a number turned out to be
wrong, the wrong version is written down too — that turned out to be the most useful habit of the
week, for reasons the last section explains.

Python 3.12 via `uv`, `ruff`, `pytest`. 186 tests. Local inference through Ollama, cloud through
Groq's free tier.

```bash
uv sync
uv run pytest
```

## The days

**[Day 1 — Byte pair encoding](day1-bpe/README.md).** Train merges, encode, decode, round-trip
Unicode, and compare against `tiktoken`. The same passage costs 1039 tokens in English, 1361 in
Romanian and 1621 in Russian — Russian is ~1.5x English for identical content. `"strawberry"` is 3
tokens in `cl100k_base` and 8 in mine, which is not a fact about the word but about the corpus: my
tokenizer never saw "berry" in 4.4K characters of Lorem Ipsum, so it fell back to near-letter
fragments. A tokenizer's vocabulary is the shape of its training data, and everything far from that
distribution pays at the till.

**Day 2 — the API, without an SDK** (`day2_client/`, `ts/`). An SSE parser written by hand, a
streaming client in Python (`httpx`) and another in TypeScript (`fetch` + `ReadableStream`),
mid-stream cancellation, backoff with full jitter, and tool calls accumulated from `input_json_delta`
fragments that only become parseable at the block-stop event. Ollama's `/api/chat` streams
newline-delimited JSON rather than SSE, which is the cheapest possible demonstration that "streaming"
is not one protocol. The deliberate bug to hit here is that network chunks do not align to SSE
events — buffer, split on `\n\n`, keep the trailing partial.

**[Day 3 — Sampling and determinism](day3_sampling/README.md).** 360 calls across two providers,
three prompts, two temperatures and two dispatch modes, stored raw in SQLite so that redefining a
metric costs a query instead of another 360 calls. Groq refuses `logprobs` on every model it serves,
so the confidence half of the day runs only against Ollama. Temperature 0 is not deterministic, and
finding out why — batching, floating-point non-associativity, routing — is the day's real content.

**[Day 4 — Embeddings and semantic search](day4_search/README.md).** 500 real Amazon ESCI products,
embedded once, L2-normalised so cosine similarity collapses to a dot product, ranked with one
matrix-vector multiply. No vector database, because at this size there is nothing for one to do.
Dense retrieval wins natural-language queries decisively — *"something to plug two headphones into
one phone"* returns the headphone splitter, where hand-rolled BM25 returns a rubber grommet and a
zinc supplement — and loses exact identifiers, which is the motivating failure for hybrid retrieval.

**[Day 5 — Python at eval scale](day5_async/README.md).** The concurrency shape every later project
uses: bounded by a `Semaphore`, failures returned as data rather than raised, each result checkpointed
to JSONL as it lands, and a resume that retries failures but never re-pays for successes. The repo
became an installable package here, because four days of scripts working by accident of `sys.path[0]`
silently caps a repo at "no file may ever be shared".

**[Day 6 — The local stack, in Docker](day6_stack/README.md).** Postgres with pgvector, Qdrant, the
app, and Ollama deliberately left on the host. A one-line source edit rebuilds in 1.0s against the
textbook multi-stage build's 9.3s, because `COPY --from=builder /app /app` produces a single 244 MB
layer holding the virtualenv and the source together. A containerised Ollama runs 4.02x slower than
the host, since Docker on macOS has no path to Metal. A memory limit is a band rather than a
threshold, the kill is invisible from inside the process, and peak RSS over-estimates what the
container needs. Alpine fails twice, in two different places, depending on where you put it.

**[Weekend — Structured output](weekend_structured/README.md).** 800 episodes: three models, three
ways of demanding a schema, 100 product titles, and a validate-repair-retry loop measured against a
control that was shown nothing. "Structured output" turns out to be three different guarantees under
one name, the 3×3 grid is really eight cells because Gemma 3 refuses tools outright, and the schema
you send is not the schema you validate against — a grammar enforces only the JSON-Schema-expressible
subset of a contract, which here is under half of it.

## The thing that kept happening

Days 5, 6 and the weekend each ended by correcting a measurement rather than a program. Six bugs in
three days, and every one of them was in the code that measures:

| day | what was wrong | what it would have reported |
|---|---|---|
| 5 | classified violations by matching message substrings; two rules shared a phrase | 22 nested-object failures filed as placeholder failures |
| 6 | the control Dockerfile did not set `UV_COMPILE_BYTECODE=1` | the naive build *beating* the optimised one |
| 6 | compared a compressed pull size against an unpacked disk size | one "image size" that was two different numbers |
| 6 | concatenated stdout and stderr instead of interleaving them | every classification of where the process died |
| weekend | control arm varied the seed at temperature 0, which greedy decoding ignores | 0% control recovery, i.e. feedback always wins |
| weekend | four concurrent requests to a daemon that serialises them | the harness's worker count, labelled as model latency |

None of them crashed. Each returned a plausible number, and the more sensible the number looked the
longer it survived — two of the six would have been published as findings. A wrong measurement is
indistinguishable from a right one at the point of reading it, which is the argument for writing down
what you expected before you run anything.
